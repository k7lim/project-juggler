# History read service, contract v1

Status: staged implementation; not deployed. This service is separate from the census UI. No private listener, credentials, or host-history mounts are enabled by installation.

Launch explicitly: `python -m pj.history_service --config /host/protected/history.json`. The operator protects the config from sandbox writes. It must be an owner-only regular file (0600), owned by the service user, in an owner-only directory (0700), with no symlink components. With `unix_socket: "/short/protected/session/history.sock"`, the server binds an AF_UNIX stream socket (0600) exclusively; its existing parent must be owner-only, the socket must not already exist, and its encoded path must be at most 100 bytes. Without `unix_socket`, the server binds only to 127.0.0.1 on `--port` (default 0, OS-selected). Nonzero `--port` and `unix_socket` conflict. External exposure, audience routing and proxy authentication are host policy; this implementation does not establish them.

Configuration (JSON, `schema_version: 1`): `token_sha256` (SHA256 of an externally generated unguessable bearer token), `expires_at` (UTC ISO timestamp with timezone), optional `audience` (`private`, default, or `approved-public`). Rotation requires replacing the protected config and restarting. Never include the plaintext token in config, process arguments, or logs. `temp_dir` names a protected owner-only directory for transient parser copies; the default is `parser-tmp` beside the config. The parent service removes each request directory even when its worker times out. For private use the launcher MUST place config and parser copies outside sandbox filesystem read grants, including broadly granted `/private/tmp` and OS temporary directories: mode 0700 alone does not isolate same-UID sandbox agents. Paths must be canonical and have no symlink components.

A private config has `roots: [{"agent":"codex","path":"/absolute/history/root"}]`; `claude_code` also supported. Each private root may be one JSONL file or a directory tree. Prefer project-scoped roots or reviewed exports; this bounded prototype does not index a whole host archive. Only these explicitly named trees/files are read, with no symlink traversal or HOME discovery. Kimi and indirect sidecar files are intentionally unsupported. An approved-public config instead has `snapshots: [{"agent":"codex","path":"/absolute/export/session.jsonl","sha256":"<64 lowercase hex>"}]`, no roots. Every listed file's bytes are hashed on every data request before parsing a private temporary copy. Any changed/missing file fails the entire request closed; newly created files are excluded. Approval covers all metadata and content in those exact files, including original workspace strings and titles. Public and private services require distinct configuration, token and corpus; the caller cannot select an audience, roots, paths or a visibility filter. A private service may live-read legacy unlabelled history; labels are not a declassification mechanism.

Every route requires exactly one `Authorization: Bearer <token>` header, including health, unknown routes and unsupported methods. Missing, wrong and expired credentials yield the same 401 JSON without corpus information. No token in URL, cookies, alternate headers or request body. Browser Origin headers and CORS preflights are rejected; no CORS grant is emitted. Authenticated GET routes only:

- `/api/health`: `data: {"status":"ok"}`, fixed audience in metadata. Does not enumerate history.
- `/api/search`: repeated `q` terms (1–8, each 1–256 characters), optional `project`, `sort=newest|oldest|relevance`, `match=any|all`, `limit` and `offset`. Literal, case-insensitive matching across approved workspace/name/title/message data; no notes/tags/census/discovery. Returns CLI-compatible project rows (`id`, `name`, `path`, `match_fields`, `matching_sessions`, `snippets`, `query_terms`, `match_mode`, `regex:false`). No regex option is accepted.
- `/api/chats`: optional `project` (literal workspace/name or ID prefix), `limit`, `offset`; returns CLI session summaries, newest first. Omitted API project means the configured corpus, never the caller's or host's cwd. The remote CLI requires an explicit project or `--here`, with no automatic discovery. Single-workspace results include `meta.project` for CLI pretty output.
- `/api/chat/<exact-session-id>`: `limit`, `offset`, optional `last`, `roles` (comma-separated user/assistant/tool/system), `include_tools=true|false` (default true), `all_branches=true|false` (default false). Exact IDs only; unknown/ambiguous IDs return 404. Returns the CLI session/message shape, with filesystem `source_path` included only for the private audience and excluded for approved-public. Claude branch/tool behavior uses existing parser; legacy non-tree Claude sessions fall back to the legacy parser. Message pagination follows roles/tools filtering, then last, offset, limit.

All responses use `{"success": bool, "data": list|dict, "meta": {...}}`. Successful metadata has `source: "history"`, `audience`, `latency_ms`; lists have `total`, `limit`, `offset`; chat additionally has `total_messages`. IDs use letters, digits, underscore and hyphen (1–128). Project selectors accept 1–512 printable characters without traversal, control characters or pre-encoding. Unknown/duplicate parameters fail closed (only q repeats). All methods other than GET return 405 after authentication. Unknown routes return 404; invalid input 400; limits 413; corpus/worker failures 503. Errors are generic and never contain host filenames, token or exceptions. No mutating endpoint, arbitrary file route, resume command, census import or discovery fallback exists.

Bounds: 4096-byte request target; 8192-byte aggregate parsed headers; 100 results/messages per page (search/chats default 20; chat 100); offset ≤100000; last ≤1000; ≤32 roots or 2000 snapshot files; ≤2000 scanned files and ≤10000 directory entries; ≤8MiB per file and ≤64MiB total corpus bytes; 1MiB response; worker timeout 3 seconds and connection deadline 5 seconds, including headers. One request at a time and a bounded socket backlog avoid unbounded workers. Corpus expansion beyond these bounds requires a separately reviewed indexing design. Oversized output fails with 413, never silently truncates. Search nested previews cap `matching_sessions` at 100 and `snippets` at 3; `matching_session_count` reports the full count and `/api/chats` paginates sessions. The request limit bounds the configured corpus before project filtering, so `project` cannot make an over-limit corpus usable; whole-archive indexing is follow-up work, not a supported claim.

Concurrency: single service request at a time; source writers may append private histories concurrently. Each parser sees one bounded byte capture; consistency across different private files is not transactional. Public snapshots are checked against fixed digests before parsing, so replacement/append races cannot add unapproved bytes. Temporary parser copies are deleted after requests. No cache, history index, annotation or source file is written. Normal stdout/stderr/logging never includes request URLs or authorization headers. Stop the process to roll back; sources are unchanged.

## Private archive catalog (staged)

For archive-wide recall, private configuration can include `index_dir: "/Users/<owner>/.local/share/yolobox/pj-history-index"`. The directory must already exist, be owner-only (0700), have no symlink components, and remain outside sandbox read/write grants. It must not be shared with an approved-public service. The service never creates or refreshes a catalog in response to an HTTP request.

The host explicitly runs `python -m pj.history_service --config /host/protected/history.json --index`. This streaming ingestion reads only enrolled JSONL roots, writes a private SQLite FTS5 trigram catalog, and returns counts plus `indexed_at` in the usual envelope. It preserves source files and does not scan unrelated home directories. A refresh reuses unchanged files, replaces changed files, and removes deleted files within enrolled directory roots. A missing enrolled root fails rather than deleting that root's history. Concurrent source changes during ingestion fail the refresh; rerun when writers are quiescent. A per-catalog writer lock and one transaction ensure queries see a complete committed generation, or 503 when no initial generation exists. Interrupted refreshes retain the previous generation.

Catalog identity includes the exact configured roots and agents. A mismatched or missing catalog produces a generic 503; there is no fallback to local discovery or direct scanning. Query connections use SQLite `mode=ro`, `query_only=ON` and `temp_store=MEMORY`; the writer also uses in-memory temporary tables and DELETE journals in the protected index directory. The catalog is mode 0600. Host stdout exposes only status/counts, never source content, filenames, credentials, queries or SQL errors.

Indexed rows use stable `session_id: "hist-<32 hex characters>"`, derived from agent plus enrolled source path, with the native parser ID retained as `original_session_id`. This keeps subagents and duplicate histories separately addressable. Pass the exact returned opaque ID to chat. Exact native IDs remain aliases only when unique in the enrolled catalog; ambiguous/unknown IDs return the same 404.

Responses have `meta.snapshot: true` and `meta.indexed_at`, explicitly identifying an indexed snapshot. Before returning selected session summaries, snippets or chat messages, the service checks source device/inode/size/mtime against the indexed version; changed or missing selected files fail with generic 503 `history index stale`, requiring an explicit host refresh. Counts and unmatched results describe the committed generation; newly created files are absent until refresh. This is not a live subscription. Literal matching includes substrings and terms split across different messages in a session. Indexed relevance orders projects by matching session count, then recency. Message branches and tool filtering are projections of the normalized stored events; raw source files are not opened for text during queries.

Indexed ingestion bounds differ from the small direct-reader bounds: at most 100000 files, 500000 directory entries, 1GiB per file and 16MiB per JSONL record. Files stream into SQLite rather than being copied into temporary transcript files or materialized as a whole corpus. A synthetic source larger than 64MiB is covered by automated ingestion and HTTP search/chat tests. Queries retain the API request/output/pagination bounds, a two-second SQLite progress deadline and the three-second worker deadline. Large chat pages fail 413 before loading oversized message bodies. SQLite FTS5 with its trigram tokenizer is required (verified against Apple Python SQLite 3.43.2). Public snapshot handling remains the original digest-verified direct path; it cannot select or read this private index.
